# contracts/

Versioned JSON Schemas shared by the backend, the cockpit and the experiments. **Draft v0.1.0.** They are a starting point for tasks DAT-01, RES-01 and DEC-01 and are reviewed by all three members before those tasks are marked done.

| Schema | Purpose | Task |
|---|---|---|
| `telemetry_record` | One normalized metric sample with source, timestamp, unit, entity id and provenance | DAT-01 |
| `asset` | A node of the topology (site, zone, rack, server, cooling unit, PDU) | DAT-01 |
| `research_case` | A case opened by detection, with trigger window, evidence references and data quality | RES-01 |
| `hypothesis` | A falsifiable explanation with supporting, weakening and missing evidence | RES-01 |
| `experiment_spec` | A bounded experiment; `sandbox_only` is always `true` | RES-01 |
| `experiment_result` | A sandbox outcome; provenance is always `SIMULATED`, with assumptions and limitations | RES-01 |
| `decision_certificate` | The auditable recommendation; advisory only; `high_impact_execution` is always `blocked` | DEC-01 |

## Provenance labels
`MEASURED` (real source, with permission) · `REPLAYED` (historical trace) · `ESTIMATED` (derived from a model or incomplete input) · `SIMULATED` (generated by the Digital Twin). Every metric carries one.

## Rules
- Unknown fields are rejected; every schema carries `schema_version`.
- Contract changes bump the version and need review from every team member.
- `fixtures/` holds valid and invalid examples; `tests/test_contracts.py` checks them and the consistency between the seven contracts.

Run: `python -m pytest contracts/tests` from the repository root.
